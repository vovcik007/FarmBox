# Процес релізу

Після злиття PR та успішного CI для відповідного commit SHA створюється анотований Git-тег. GitHub Release публікується для цього тега з описом змін та посиланням на PR. Тег, GitHub Release і розгортання в production — окремі операції; публікація артефакту сама по собі не означає розгортання.

Для лабораторної заплановані `v1.0.0` (резервування), `v1.0.1` (hotfix) і `v1.1.0` (ідемпотентність). Версії та PR не вважаються виконаними, доки вони не з’являться у фактичній історії репозиторію з успішними перевірками. Опубліковані теги не пересуваються. Production-інфраструктура в демонстрації не створюється.

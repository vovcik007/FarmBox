# Середовища та план розгортання

| Середовище | Призначення | Дані | Зовнішні інтеграції |
|---|---|---|---|
| local | Розробка і ручна перевірка | Seed-дані | Моки або sandbox |
| test | Автоматизовані перевірки | Ізольовані тестові fixtures | Моки або тестові сервіси |
| staging | Перевірка кандидата | Синтетичні або знеособлені | Sandbox |
| UAT | Приймання бізнес-сценаріїв | Підготовлені приймальні набори | Sandbox |
| production | Робота користувачів | Реальні | Реальні інтеграції |

Для local передбачено `docker compose up --build`; доступність команди потрібно перевірити на машині з Docker. Кожне віддалене середовище має запускати вибрану версію незмінного артефакту з окремою конфігурацією, ізольованими доступами та секретами в сховищі середовища. Секрети не входять до образу чи репозиторію.

План: PR checks → збірка незмінного артефакту → test → staging → UAT → production після відповідних gates. Між середовищами просувається той самий артефакт без повторного збирання. UAT передає результат автоматизованих сценаріїв або зафіксоване бізнес-погодження згідно з політикою команди; окрему обов’язкову кнопку production тут не передбачено.

Production планується оновлювати поступово: readiness checks, поетапна заміна екземплярів зі збереженням достатньої кількості працездатних, graceful shutdown, smoke tests і контроль помилок. У разі проблем rollout зупиняється та повертається сумісний попередній артефакт. Сумісність API та схеми підтримується підходом expand–migrate–contract; відкат коду автоматично не скасовує зміни даних чи фінансові операції.

У демо є конфігурація Docker Compose і CI; фактичне розгортання віддалених середовищ, просування артефакту та rolling update є архітектурним планом, а не реалізованою інфраструктурою.

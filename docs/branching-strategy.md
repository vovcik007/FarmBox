# Стратегія гілок FarmBox

Використовується GitHub Flow: довгоживуча гілка `main` і короткоживучі `feature/*`, `hotfix/*` та, за потреби, `docs/*`. Середовища не є гілками; міста задаються конфігурацією та даними. Frontend і Android мають окремі репозиторії з аналогічними правилами.

Розробник оновлює `main`, створює гілку, виконує локальні перевірки, публікує її та відкриває PR. Після успішного CI і незалежного review, коли є інший учасник, зміни зливаються в `main`; завершену гілку видаляють. Для наочного графа в цій роботі заплановано merge commit; GitHub Flow також допускає інші способи злиття.

Якщо під час розробки функції виникає hotfix, його виконують від актуального `main`, проводять через PR та перевірки, а потім зливають оновлений `main` до незавершеної feature-гілки. Це план сценарію: факти виконання потрібно підтвердити посиланнями на PR, CI та графом.

## Захист main

Для командної роботи в Settings → Branches → Add branch protection rule виберіть `main`, увімкніть вимогу PR та одного approval, required status checks `lint`, `typecheck`, `unit`, `integration`, `build`, забороніть force push і видалення гілки. Автор не може схвалити власний PR: для наступних змін потрібен інший учасник. Доступність правила залежить від прав і тарифу; описані кроки самі по собі не означають, що захист увімкнений. Фактичний стан перевіряйте в налаштуваннях GitHub.
